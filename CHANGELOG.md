# Changelog

All notable changes are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project uses [semantic versioning](https://semver.org/).

## [Unreleased]

## [0.3.0] – 2026-10-28

### Added
- Follow Jira and GitLab boards with `jira.watch_boards` and `gitlab.watch_boards`: paste the board links from the browser. Their open issues, board and backlog, appear in a new Boards column on the Issues tab and as "From your boards" at the end of Next up, so you can pick your next task there. Issues you are already involved in stay where they were.

## [0.2.1] – 2026-10-28

### Fixed
- On the dashboard, a long "Follow up" list no longer squeezes "Since your last visit" down to its header. Both cards share the height evenly; a short one gives its unused space to the other.

## [0.2.0] – 2026-10-28

### Added
- Jira also finds issues where you are a request participant (Jira Service Management) or mentioned in the description or a comment. A mention counts as answered once you comment after it. Instances that do not support these searches skip them quietly.

## [0.1.5] – 2026-10-27

### Added
- GitLab issues take their status from board lists made of plain labels ("Doing", "Test"), not only from `workflow::` or `status::` labels. With several, the right-most list wins, as on the board.
- "Next up" shows issues in a test, QA or review status as their own group, "In test or review", at the bottom.
- Pull requests link the Jira issues they name in the title or branch, or link in the description. A Jira issue in turn lists the PRs that name it.

### Fixed
- Opening or closing an item no longer scrolls its column back to the top.
- Clicking the text of the "Pull Requests" tab opens it; before, only a click on the tab's edge did.

## [0.1.4] – 2026-10-23

### Fixed
- After installing with pip or pipx, the first-run help and the token hints show `onmyplate --set-token …` instead of `python3 onmyplate --set-token …`, which failed with "No such file or directory". Started as a script they still show `python3 onmyplate.py`.

## [0.1.3] – 2026-10-22

### Fixed
- `--update` for pip installs always reinstalls the checked wheel and then confirms that Python finds the new version; before, it could report success when pip had skipped the install.

## [0.1.2] – 2026-10-22

### Added
- `--update` installs the latest release from GitHub after checking every file against its `SHA256SUMS`: it replaces the script (keeping the old one as a backup) or reinstalls the package with pipx or pip. It runs only when you ask for it.

### Fixed
- Opening an item in "Since your last visit" no longer makes it vanish: it stays in place, marked as seen, until the next refresh. The same applies to the "New / changed" groups of the other views.
- In demo mode a refresh no longer marks every item as changed.
- The quick start downloads the latest release instead of the unreleased `main` branch.

## [0.1.1] – 2026-10-22

### Security
- **Tokens are no longer stored in plain text.** They live in the system keychain (macOS Keychain, the Secret Service on Linux, Windows Credential Manager), bound to the host of the configured URL. `--set-token` and `--delete-token` manage them; `"token_command"` can fetch them from a password manager instead.
- Configs that still contain a `"token"` are cleaned up on the next start or refresh: the token moves into the keychain and is removed from the file. Without a keychain, such a config is refused.

## [0.1.0] – 2026-10-21

First public release.

### Added
- **Sources**, all read-only:
  - Jira Data Center/Server and Jira Cloud, including scoped API tokens.
  - GitLab self-managed and gitlab.com. Work items (tasks, epics, objectives …) count as issues.
  - Bitbucket Data Center with a personal HTTP access token.
- **Views:** a dashboard with "Next up", "Since your last visit" and "Follow up", plus Issues, Pull Requests and List views.
- **Personal tasks** in a Markdown checklist, a focus list, private notes, seen tracking and hiding, with undo.
- **Setup without restart:** Refresh reads `onmyplate.config.json` again. The ? dialog lists every source with its status, URL and where its token comes from.
- **Commands:**
  - `--export` / `--import` to move to a new machine.
  - `--demo` with sample data.
  - `--port 0` for a free port.
  - `--licenses`.
  - `--rotate-key`.
- **UI:**
  - Light and dark theme, keyboard shortcuts.
  - Layouts for wide screens, laptops from 900 px and phones.
  - Screen reader support with real focus, headings, labels and a live region.
  - Text contrast that meets WCAG AA.
- **Licenses:** the MIT license and the third-party notices are shown under ? > About & licenses, generated by `tools/third_party_licenses.py` and checked in CI. A `NOTICE` file covers trademarks and the task file format.
- **Project:**
  - A website with a live demo that runs in the browser and is recorded from the real server.
  - `AGENTS.md`, a code of conduct, issue and pull request templates.
  - CI on Python 3.11–3.14, Conventional Commits checked in CI and by git hooks.
- **Security:**
  - One-time sign-in links. The session token travels in a request header and ends when On My Plate stops.
  - Host, Origin and Sec-Fetch-Site checks.
  - Hash-based CSP.
  - Same-origin-only redirects.
  - Bounded responses.
  - DTD-free XML parsing.
  - Server fields checked and cleaned before they reach the UI.
  - A config that another user could change is refused, so nobody can redirect tokens.
